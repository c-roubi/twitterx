# SmartEngage — إدارة تفاعل ذكية لتويتر

أداة تدير **50 حساب تويتر** بسلوك يحاكي البشر: تتابع تغريدات المدير، وعند نزول تغريدة جديدة توزّع **لايك + ريتويت + تعليق** على مجموعة عشوائية من الحسابات **بجدول زمني متدرج** (وليس دفعة واحدة)، وتمنح كل حساب **نشاطًا يوميًا عشوائيًا طبيعيًا** (لايكات وتفاعلات متفرقة على مدار اليوم) بحيث لا يبدو أي حساب "آليًا".

كما تنمو الحسابات **تدريجيًا وبطريقة بشرية**: كل حساب يضيف **5–10 متابعين يوميًا** من المهتمين بالكريبتو (حساب جديد يبدأ أخف ويتدرج حتى الهدف الكامل خلال ~7 أيام)، مع **جلسات إحماء يومية** تُبقي الحساب نشطًا حتى في الأيام التي لا ينشر فيها المدير شيئًا.

> ⚠️ **مهم جدًا قبل الاستخدام:** الأداة تعمل عبر متصفح حقيقي (Playwright) ببروفايل منفصل لكل حساب. **الأفضل دائمًا استخدام بروكسيات** (قسم البروكسيات أدناه) بحيث يخرج كل حساب من عنوان IP خاص به. بدون بروكسيات كل الحسابات من نفس عنوان IP — وهذا أكبر عامل خطر. الأداة مبنية لتقليل هذا الخطر قدر الإمكان (تفاوت زمني، تدوير الحسابات، نشاط يومي عشوائي، حدود يومية)، لكن **لا يوجد حل يضمن 0% حظر** من تويتر. ابدأ بعدد قليل من الحسابات (3–5) لمدة أسبوع وراقب، ثم زد العدد تدريجيًا.

---

## المتطلبات

- **ويندوز 10/11** (أو لينكس) مع سطح مكتب
- Python 3.9+ مثبت (من [python.org](https://python.org) — فعّل "Add to PATH" أثناء التثبيت)
- كل حساب تويتر مسجّل دخول مرة واحدة يدويًا (خطوة `login`)

## التثبيت

```bash
cd twitter-engage
pip install -r requirements.txt
python -m playwright install chromium
```

> على لينكس بدون واجهة رسومية أضف: `python -m playwright install-deps`

## الإعداد (مرة واحدة)

### 1) إنشاء الملفات

```bash
python main.py init
```

### 2) ضبط حساب المدير

افتح `data/config.json` وعدّل:

```json
"manager_handle": "اسم_المدير_بدون_@"
```

### 3) إضافة الحسابات

```bash
python main.py add --handle account1 --username "الاسم الظاهر"
python main.py add --handle account2 --username "الاسم الظاهر" --en-ratio 1.0
# ... كرر لكل حساب
```

`--en-ratio` (اختياري، 0–1) يحدد نسبة التعليقات الإنجليزية لهذا الحساب تحديدًا:
`0` = كل التعليقات عربية، `1` = كلها إنجليزية. عند تركه، يتبع الإعداد العام `comments.en_ratio` (افتراضي 0.9).

### 4) البروكسيات (موصى بها بشدة لـ 50 حسابًا)

افتح `data/config.json` وضع قائمة بروكسياتك داخل قسم `proxies`:

```json
"proxies": {
    "enabled": true,
    "list": [
        "socks5://user:pass@1.2.3.4:1080",
        "socks5://5.6.7.8:1080",
        "http://proxy.example.com:8080"
    ],
    "fallback_to_direct": true,
    "test_timeout": 10,
    "rotate": false
}
```

- **توزيع ثابت**: كل حساب يرتبط ببروكسي واحد ثابت (حسب معرّفه) ولا يتغير بين التشغيلات — نفس الحساب دائمًا من نفس IP.
- **اختبار مسبق**: قبل فتح أي متصفح يُختبر البروكسي بفتح اتصال حقيقي إلى `x.com`، ولا يُستخدم إلا إذا نجح (النتيجة تُخزن 15 دقيقة لتجنب بطء الفتح).
- **رجوع تلقائي**: إذا تعطّل بروكسي حسابٍ ما، يتحول الحساب تلقائيًا للاتصال المباشر بدلًا من التوقف (`fallback_to_direct: true`) — الحسابات لا تتعطل أبدًا.
- `rotate: true` = تدوير البروكسيات كل ساعة بدل التوزيع الثابت (غير موصى به عادةً).
- الصيغ المقبولة: `socks5://host:port` أو `socks5://user:pass@host:port` أو `http://host:port` أو `host:port`.

### 5) تسجيل دخول كل حساب (مرة واحدة)

```bash
python main.py login acc_001
```

ستفتح نافذة متصفح → سجّل الدخول يدويًا (اسم مستخدم + كلمة مرور + رمز التحقق إن وجد) → ارجع للطرفية واضغط Enter. الجلسة تُحفظ تلقائيًا ولا تحتاج إعادة تسجيل إلا إذا انتهت.

> الحسابات في الاختبار التجريبي قبل نشر الأداة: جرّب أولاً بـ 3 حسابات لمدة أسبوع.

## التشغيل

### أمر واحد يشغّل كل المهام (الوضع الطبيعي)

```bash
python main.py monitor
```

**أمر واحد** يعمل على مدار الساعة ويقوم تلقائيًا بكل المهام:
1. **فحص تغريدات المدير** كل 6–14 دقيقة (فاصل عشوائي).
2. عند تغريدة جديدة: يختار **6–12 حسابًا عشوائيًا** من أصل 50 ويوزع عليهم المهام (لايك/ريتويت/تعليق) بجدول ممتد على **30 دقيقة إلى 4 ساعات**.
3. **روتين يومي لكل حساب**: 1–3 جلسات في أوقات عشوائية بين 8 صباحًا و11 مساءً، كل جلسة 15–35 دقيقة تصفح مع لايكات عشوائية وريتويتات قليلة، ضمن حدود يومية (لايك 25–45، ريتويت 2–6، تعليق 1–4، متابعة 5–10) + **جولة متابعات كريبتو بطيئة** (1–3 متابعات/جلسة بفاصل 90–300 ثانية). كل تفاعلات المدير تُحتسب ضمن نفس الحدود اليومية، وتتدرج الحدود مع عمر الحساب، و12% من الأيام تكون أيام راحة كاملة (تصفح فقط).
4. **إحماء يومي تلقائي**: وقت عشوائي يومي لكل حساب (يظهر في `status` كـ `إحماء HH:MM`)، يفتح الحساب ويتفاعل مع الكريبتو حتى في الأيام بدون تغريدات مدير.
5. يوقف الحساب مؤقتًا ويرشده لإعادة تسجيل الدخول إذا انتهت جلسته.

لتنفيذ **دورة واحدة فقط** (بدون تشغيل مستمر) أضف `--once`:

```bash
python main.py monitor --once
```

### أوامر أخرى

| الأمر | الوظيفة |
|---|---|
| `python main.py list` | عرض الحسابات وحالة جلساتها |
| `python main.py status` | حدود اليوم المنجزة لكل حساب + المهام المعلقة |
| `python main.py check` | فحص تغريدات المدير مرة واحدة وجدولة أي جديد |
| `python main.py daily acc_001` | تشغيل جلسة يومية لحساب معين فورًا |
| `python main.py daily acc_001 --dry-run` | محاكاة بدون فتح متصفح (للتجربة) |
| `python main.py warmup acc_001` | جلسة إحماء خفيفة (فتح تويتر + تفاعل كريبتو) — لا تُحتسب ضمن جدول الجلسات اليومي |
| `python main.py warmup acc_001 --dry-run` | محاكاة جلسة الإحماء بدون متصفح |
| `python main.py monitor --dry-run` | تشغيل كامل بدون أي تفاعل حقيقي |
| `python main.py monitor --once` | دورة واحدة فقط (فحص + جلسات + إحماء) ثم الخروج — مناسبة لجدولة windows |
| `python main.py login acc_001` | إعادة تسجيل الدخول لحساب |

## النمو اليومي (متابعات الكريبتو) والإحماء

### كيف تعمل المتابعات؟

كل جلسة يومية تحسب **هدف اليوم**: حساب جديد يبدأ خفيفًا (عامل 0.4 + 0.6 × تقدم الأيام) ويتدرج حتى الهدف الكامل (`daily_target` = 5–10) بعد **7 أيام** (`ramp_days`). **نفس منحنى التدرج يُطبَّق على سقوف التفاعلات اليومية** (لايك/ريتويت/تعليق) وليس فقط على المتابعات. الجلسات تختار استعلام كريبتو عشوائيًا (`follow.queries`) وتفتح نتائج البحث `f=user`، ثم تفحص الحسابات بشرط: سيرة ذاتية، عدد متابعين ضمن النطاق، وغير موثّق (كلها قابلة للضبط).

- المتابعة تتم بفتح البروفايل أولًا وقراءته، ثم hover على زر المتابعة والضغط والتحقق — مع **25% احتمال زيارة فقط بدون متابعة** (`visit_only_chance`) لإخفاء النمط.
- التأخير بين المتابعات **90–300 ثانية** (`delay_between_s`) — بطيء عمدًا، والحد الأقصى للجلسة الواحدة 1–3 متابعات (`per_session`).
- تُحفظ المتابعات الناجحة في `data/state/` ولا تتكرر نفس الحسابات التي شوهدت سابقًا، وعند بلوغ هدف اليوم تتوقف الجولة.
- **أيام أخف**: 30% من الأيام تلقائيًا هدف متابعات أقل (50–85% من المعتاد) لتفادي نمط ثابت يوميًا.
- **أيام راحة كاملة**: `behavior.rest_day_chance` (افتراضي 12%) يجعل بعض الأيام بلا أي تفاعل (لايك/ريتويت/تعليق/متابعة) — تصفح سلبي فقط.

### الإحماء اليومي

حتى في الأيام التي لا ينشر فيها المدير شيئًا، يبقى الحساب نشطًا:

```bash
python main.py warmup acc_001
```

يفتح الحساب تويتر ويتصفح بحث الكريبتو المباشر (`f=live`) مع لايكات خفيفة ضمن الحدود اليومية، ولمدة 8–15 دقيقة (`warmup.session_minutes`). جلسة الإحماء **لا تُحتسب ضمن جدول الجلسات اليومي** (`sessions_per_day`) حتى لا تزاحم جلسات الروتين العادية.

**التشغيل المستمر (`monitor`) يجداول الإحماء تلقائيًا**: لكل حساب وقت عشوائي يومي (`warmup_at` ضمن ساعات النشاط) يُنفَّذ الإحماء عنده مرة واحدة يوميًا — لا حاجة لأي تدخل. `status` يعرض موعد الإحماء وحالته (`معلق` / `تم ✓`).

## التعليقات (محرك ذكي)

محرك التعليقات يختار التعليق حسب ترتيب الأولوية التالي:

1. **AI (اختياري)**: إن فعّلت `comments.ai` بمفتاح صحيح، يُولَّد تعليق من نص التغريدة عبر Gemini/OpenAI/Groq.
2. **سياقي**: كشف موضوع التغريدة (كريبتو: BTC/ETH/Altcoins/صعود/هبوط/تحليل/DeFi/NFT/أخبار/منصات تداول/… بمعجم عربي+إنجليزي) ثم اختيار قالب مخصص (إنجليزي غالبًا) من `data/comments_crypto.json`. المحرك يتعرّف أيضًا على أسلوب حسابات الإشارات (ضخ 🚀، جني أرباح/أهداف، اختيار عملات/توصيات، تحليل فني ووقف خسارة، إلغاء توصية/إخلاء مسؤولية، حماس/استعدادات) بـ 21 موضوعًا و125 قالبًا عربيًا + 128 قالبًا إنجليزيًا.

   كما يلتقط رمز العملة بنمط `$TICKER` (مثل `$EPIC`) من تغريدات الضخ التي يكتبها المدير، ويدرج اسم العملة داخل بعض التعليقات (مثل «EPIC إلى القمر 🚀») عبر القوالب التي تحتوي على `{TICKER}` — وتُدمج مع قوالب مواضيع الضخ واختيار العملات لتقليد أسلوب المدير. القوالب الإنجليزية تحمل `${TICKER}` فتُعرض بصيغة `$EPIC` تمامًا كأسلوب حسابات الإشارات، وعند وجود رمز في التغريدة تنحاز 80% من التعليقات الإنجليزية للقوالب التي تذكره.
3. **عام**: قوالب `data/comments.txt` العادية.

كل طبقة تفشل بأمان (بدون مفتاح/بدون إنترنت → الطبقة التالية). اللغة تُختار عشوائيًا بنسبة `comments.en_ratio` (افتراضي 0.9): 90% تعليقات إنجليزية بأسلوب متابعي الكريبتو، و10% عربية بلهجة خليجية — وأغلب التعليقات الإنجليزية على تغريدات الضخ تبدأ بـ `$` ورمز العملة. لا يتكرر نص التعليق نفسه على نفس التغريدة، وكلها بدون وسوم (هاشتاغ).

```
ماشاء الله {تبارك الله|عليك}، {موضوع رائع|طرح مميز} {شكراً لك|يعطيك العافية}
```

- `data/comments_crypto.json`: قوالب مواضيع الكريبتو — عدّلها أو أضف مواضيع/قوالب جديدة، وتُدمج تلقائيًا مع الافتراضية. أي قالب يحتوي `{TICKER}` لن يُستخدم إلا إذا كانت التغريدة تذكر رمز عملة `$...`.
- `data/comments.txt`: القوالب العامة — أضف قوالب خاصة بمجالك؛ كلما زاد التنوع قلّت احتمالية الاكتشاف.

## مقاومة تغييرات واجهة X (المحددات والذكاء)

واجهة تويتر/إكس تتغير باستمرار، لذلك جُمعت كل المحددات في `app/selectors.py` كنقطة صيانة واحدة، وكل زر/حقل يُعرَّف كقائمة بدائل مرتبة حسب الأولوية بدلًا من سلسلة واحدة هشّة:

- **ريتويت → إعادة نشر (Repost)**: يجرّب `retweet` ثم `repost` ثم `aria-label="Repost"` و`إعادة نشر`، وكذلك زر التأكيد `repostConfirm`.
- **صندوق الكتابة**: تحوّل من `<textarea>` إلى `div[contenteditable]` — يدعم الاثنين تلقائيًا.
- **زر الإرسال**: يدعم `tweetButtonInline` و`tweetButton`.
- **المتابعة/البروفايل**: زر متابعة خاص بالحساب ثم عام ثم `aria-label="Follow"`، وخلايا النتائج تدعم `UserCell` و`TypeaheadUser`.
- **الدوال المساعدة** `first`/`has`/`all_of` تجرّب كل مرشح بترتيب الأولوية وتأخذ أول عنصر ظاهر، بدلًا من الاعتماد على محدد واحد.
- **إخفاء الأتمتة**: بصمة المتصفح تُخفي `navigator.webdriver` وتضبط `languages/platform/chrome` داخل كل صفحة.

عند تغيير تويتر لأي عنصر، عدّل فقط `app/selectors.py` وأضف المحدد الجديد إلى رأس القائمة — دون لمس منطق التفاعل في باقي الملفات.

## طبقة المرونة (resilience)

حتى لا يتوقف التشغيل عند أي عطل، أُضيفت طبقة مرونة تعمل تلقائيًا خلف الكواليس:

- **تصنيف الأخطاء**: كل خطأ يُصنَّف تلقائيًا (شبكة / مهلة / عنصر مفقود / تغريدة محذوفة / حائط تسجيل دخول / غير معروف) في `app/resilience.py`.
- **إعادة المحاولة والتراجع**: أخطاء الشبكة والمهل تُعاد المحاولة عدد مرات `resilience.network_retries` مع انتظار يبدأ من `resilience.retry_base_delay_s` ثانية ويتضاعف بين كل محاولة (backoff) — فلا يُهدر الإجراء بسبب انقطاع لحظي.
- **كشف التغريدة المحذوفة**: عند فتح تغريدة حذفها المدير (أو أصبحت غير متاحة)، يتعرّف عليها `open_tweet` ويعلّمها محذوفة بدل المحاولة إلى ما لا نهاية، وتُستبعد من قائمة الانتظار.
- **تخطي الإجراء الفاشل**: كل إجراء (لايك/ريتويت/تعليق/متابعة/بحث) له حد أقصى من المحاولات `resilience.action_max_attempts`؛ بعدها يُعلَّم «فشل نهائي» ويُتخطّى دون إيقاف بقية العمل.
- **حائط تسجيل الدخول**: إذا طلب تويتر إعادة تسجيل الدخول أثناء التنفيذ، يتوقف الحساب بأمان وتظهر علامة «إعادة دخول» في `status` بدل تكرار الفشل.
- **المراقبة مستمرة**: دورة `monitor` تعيد جلب تغريدات المدير عند فشل الشبكة (`resilience.monitor_fetch_retries`) ثم تستمر بالفاصل الزمني الثابت دون انحراف.

ويعرض `python main.py status` ثلاث مقاييس إضافية:

```text
مهام تفاعل معلّقة: N
تغريدات محذوفة (مُهمَلة): N
عمليات متخطّاة (فشل نهائي): N
```

## نصائح لتقليل خطر الحظر

1. **استخدم بروكسيات** بحيث يخرج كل حساب من عنوان IP ثابت خاص به (قسم البروكسيات أعلاه) — أهم خطوة لـ 50 حسابًا. الأداة تختبرها تلقائيًا قبل كل فتح وتتحول للمباشر عند تعطلها حتى لا يتوقف شيء.
2. **ابدأ صغيرًا**: 3–5 حسابات أسبوعًا، ثم زد تدريجيًا. الحسابات الجديدة لا تدخل التشغيل الجماعي حتى تكمل 2–4 أسابيع نشاط طبيعي.
3. **لا تشغّل كل الحسابات من نفس الجهاز في نفس اللحظة** — الأداة تفعل ذلك تلقائيًا بالتدرج، فلا تزيد `accounts_per_tweet` أكثر من 12.
4. **نوّع التعليقات**: أضف قوالب في `comments.txt` و`comments_crypto.json` (250+ قالبًا مدمجًا: 125 عربيًا + 128 إنجليزيًا عبر 21 موضوعًا) — المحرك السياقي يختار قالبًا مناسبًا لموضوع التغريدة تلقائيًا ولا يكرر نصًا حرفيًا أبدًا.
5. **شغّل على شبكة مستقرة** (منزلي/مكتبي) ولا تغيّر الشبكة كثيرًا بين الجلسات.
6. **لا ترفع الحدود اليومية** في `config.json` — الأقل دائمًا أكثر أمانًا. خاصةً `follow.daily_target` (5–10) و`follow.delay_between_s` (90–300 ثانية): متابعات سريعة أو كثيرة = إنذار فوري لتويتر.
7. **راجع `status` يوميًا** وإذا ظهرت علامة "إعادة دخول" لأي حساب، أعد تسجيل دخوله فورًا ولا تتركه.
8. إذا لاحظت أي "تحقق أمني" (challenge) على حساب — أوقفه (`"enabled": false` في `accounts.json`) حتى تتأكد أنه سليم.

## حل مشكلة "جلسة الضيف محجوبة"

إن ظهرت رسالة `blocked-empty` عند `check` (يحدث أحيانًا من عناوين مراكز البيانات)، فعّل الفحص بحساب حقيقي في `config.json`:

```json
"monitor": { "method": "account", "use_account": "acc_001", "interval_min": [6, 14] }
```

وتأكد أن `acc_001` مسجّل دخول وأنه يتابع حساب المدير.

## ملاحظات أمان
